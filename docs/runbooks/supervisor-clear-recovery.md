## Supervisor clear recovery (Coach Ed, 2026-11-16)

Manager owns Supervisor clear AND resume; never assign Coach Ed the /clear-and-paste job. This supersedes older manual fallback wording for a Supervisor with a Manager. It does not change Manager self-handover or Builder/sub-agent ownership.

1. Before exhaustion, Supervisor saves a complete state file AND the exact resume prompt in a sibling .resume.txt file. Include late approvals/Next changes in saved state before clear, rather than only in a chat message. Manager reads and verifies both absolute paths, task/session/worktree identity and first Next. Preserve running previews and unfinished work.
2. Supervisor sends “Handover written, ready to be cleared” with both paths, then ends its turn. Manager waits for idle and inspects available session/activity/background-task metadata. Attempt the supported clear; follow an explicit supported retry instruction if returned.
3. If refused for “live work”, record the exact result and identify the blocker where metadata permits. Do not infer that a preview caused it. Wait for an active turn/agent to finish safely and avoid redundant queued messages. Never kill previews, interrupt writes, stop unrelated work, detach a user's client or bypass a permission denial to force clear. Retry only after a relevant state change; avoid a tight retry loop.
4. If parent clear remains refused, Manager may explicitly direct that Supervisor to use the supported self-clear route. This is an authorized exception to “stop without clearing self”, only after saved state/prompt verification. Supervisor ends its turn immediately after successful self-clear; it must not refuse solely because normal handover is parent-owned. Manager remains responsible for sending the saved prompt after clear is confirmed, once, and checking the resumed session's identity and acknowledgment. Do not send the prompt into the old conversation. Duplicate requests reuse the saved prompt; no repeated context dumps or new helper sessions.
5. If self-clear is unavailable, denied, or cannot execute at a hard limit, preserve state and mark recovery blocked with exact attempted routes/results and next safe check. Continue unaffected work. Do not claim a successful clear/resume or invent a tool capability. If actual app access/permission needs Coach Ed, request only that specific intervention with evidence; Manager still owns clear/prompt delivery afterward. Do not repeat an unchanged request after an Assistant Manager message or Manager handover.
6. On resume, Supervisor acknowledges Manager internally; Manager checks state/first Next, removes stale recovery blockers and continues supervision. No routine owner-facing success message.
